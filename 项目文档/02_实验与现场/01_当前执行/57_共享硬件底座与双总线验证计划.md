# 共享硬件底座与双总线验证计划

> 更新时间：2026-08-01  
> 用途：把 GM1/EtherCAT、STM32/CANopen 与 Windows-PCAN 研究路线统一到同一套安全底座下。Windows-PCAN 对 Node 1、1 Mbps 的固定单轴 PPM 控制—采集已完成一次现场闭环；GM1 与 STM32 路线仍未获得写控制或运动放行。

## 1. 先固定总口径

当前台架不是两套电机系统。两条候选路线共用同一套执行硬件：

```text
DS-BVM 驱动器
-> 30ZWWC65TEK5B-1 电机 U/V/W
-> 电机编码器
-> 两根白线刹车
-> J13 STO / GPI / GPO
-> 24 V 电源与安全回路
```

各路线唯一分歧在主控制器和总线层；Windows-PCAN 是本阶段快速研究路线，不改动共享电机侧底座：

| 层级 | GM1/EtherCAT 路线 | STM32/CANopen 路线 |
|---|---|---|
| 主控制器 | Panasonic GM1 | STM32H743 板 |
| 总线物理层 | EtherCAT RJ45 / ECAT IN | CAN 收发器、CANH/CANL/GND |
| 协议/对象 | ESI/XML、PDO、EtherCAT 状态 | CANopen 节点号、波特率、NMT、SDO/PDO |
| 共享硬件 | DS-BVM、电机、编码器、刹车、STO、电源、ServoStudio 参数 | 同左 |

**安全红线**：不能通过 CANopen/EtherCAT 总线做 Servo On、Jog、写 `0x6040` 使能或释放 Z 轴风险状态。USB+Servo Studio 低速 Jog 和读数观测是当前允许的调试操作（参见 `60_实验室推进记录/2026-06-12_接线理清_光栅反馈ServoStudio观测.md`）。

**2026-08-01 有界例外已完成**：经用户现场确认机械余量、无报警、独立停止手段并明确授权，Windows-PCAN 固定 PPM `+5000/-5000 counts` 已完成且实验后 Disable。该证据只适用于记录中的固定路线与轨迹，不把上面的通用红线改写成对 GM1、STM32或任意 CANopen 命令的普遍放行。

### 1.1 Windows-PCAN 研究路线当前事实

```text
Windows motion_acquisition 独立控制窗口
-> XCAN-USB / PCAN_USBBUS1
-> CANopen NMT + SDO
-> DS-BVM Node 1 / 1 Mbps
-> 单轴 PPM +5000/-5000 counts
```

正式会话位于 `motion_acquisition\data\20260801\2026\08\20260801_233700_run-3a2bfcc9`。该路线的软件、控制字、Manifest 标记和控制日志与 STM32 路线分开，不将 PC 端验证结果冒充 STM32 固件证据。

## 2. 现场执行顺序卡

现场不要从“想走哪条总线”开始，而要从共享底座开始。按下面顺序执行，中间任何一格不通过，都不要跳到后面的运动或写对象步骤。

| 顺序 | 动作 | 可做 | 禁止 |
|---:|---|---|---|
| 1 | 拍照和断电核对 | 拍 DS-BVM、J13、J201、CAN、ECAT、STM32、GM1、电机线束 | 带电插拔、猜端子方向 |
| 2 | 共享底座只读/静态检查 | 量 U/V/W 电阻、刹车电阻、CAN 终端、24 V/5 V 极性，备份 ServoStudio 参数 | CANopen/EtherCAT 总线 Servo On/Jog 禁止（USB+Servo Studio 低速 Jog 允许） |
| 3 | 选择一条主站路线 | GM1/EtherCAT 或 STM32/CANopen 二选一记录 | 两个主站同时控制 DS-BVM |
| 4A | GM1/EtherCAT 差异层 | 扫描从站、读 `0x6041/0x6061/0x6064` | 写 `0x6040`、PPM 小步 |
| 4B | STM32/CANopen 差异层 | 查固件、测 CAN、监听 heartbeat/EMCY、SDO 只读 | 写 PDO、写 `0x6040`、NMT 启动运动 |
| 5 | 运动前共享检查 | 逐项关闭刹车、STO、编码器、电机参数、防坠、限位 | 任一项缺证据时继续推进运动 |

## 3. 立即停止条件

出现下面任一情况，现场动作停在当前阶段，先记录照片、报文、报警和测量值：

| 停止条件 | 处理 |
|---|---|
| CANH-CANL 短路、开路或终端电阻不可解释 | 不上 CAN 电，回查线缆和终端 |
| STM32 FDCAN 引脚直接接到 DS-BVM CANH/CANL | 立即断开，必须加 CAN 收发器 |
| DS-BVM、STM32、USB-CAN 之间 GND 电位差异常 | 不共地，改查隔离 CAN 或电源地 |
| ServoStudio 报 STO、反馈、过流、编码器、刹车相关报警且原因未解释 | 不 Servo On，不点动 |
| 刹车白线电阻近似短路/开路，或限流 24 V 测试发热异常 | 不释放刹车，不进入运动 |
| U/V/W 三相电阻不平衡或对壳绝缘异常 | 不接主电，不使能 |
| SDO 返回 abort 或总线错误帧持续出现 | 停止发 SDO，记录请求/响应和错误帧 |
| 有人准备同时接 GM1 EtherCAT 和 STM32 CANopen 发控制命令 | 只保留一个主站，另一路退出控制 |

## 5. 共享硬件底座

这一节两条路线共用。不要为 STM32/CANopen 另写一套电机、编码器、刹车或 STO 接线。

### 5.1 携带工具

- 相机或手机：拍 DS-BVM 接口板、J13、J201、电机线束、24 V 电源、刹车线。
- 万用表：通断、电阻、24 V、5 V、CAN 终端、电源地电位差。
- 限流 5 V 电源：Ri、编码器、霍尔独立体检。
- 限流 24 V 电源：刹车白线短时释放/抱闸测试。
- ServoStudio：备份 DS-BVM 参数、读取报警、反馈、状态对象。
- 当前执行文件：`39_上电前逐线放行矩阵.md`、`40_逐线验收记录表.md`、`46_未闭环逐线缺口清单.md`、`50_一页上电放行卡_零基础版.md`。

### 5.2 操作

1. 断开 GM1、STM32、DS-BVM、Ri、刹车电源，确认平台机械支撑到位。
2. 拍照记录 DS-BVM 完整型号、接口板丝印、CAN/ECAT/USB/J13/J201 位置。
3. 一次只保留一个运动主站参与验证：
   - 走 GM1/EtherCAT 时，STM32 不接入 DS-BVM 控制总线。
   - 走 STM32/CANopen 时，GM1 不向 DS-BVM 发运动命令；EtherCAT 线是否保留只用于现场记录，不允许两个主站同时控制同一驱动器。
4. 在 ServoStudio 中连接 DS-BVM，先导出原始参数；记录驱动器型号、固件版本、报警、反馈类型、电机参数页面。
5. 只按已有证据处理电机线：
   - 三根粗线为电机 U/V/W，当前证据指向 `U=棕、V=黄、W=绿`，仍要现场三相电阻、对壳绝缘和低风险验证。
   - 两根白线为刹车，只做断电电阻和限流 24 V 短时测试；不接 U/V/W，不接 J201 5 V/GND，不接 GPO 直驱。
   - 八根细线为编码器，应接 DS-BVM 编码器口；具体 pin、极性、CPR、反馈类型以手册、现场图纸、厂家或实测为准。
6. 对 J13 只做识别和限流验证：
   - `STO` 不永久短接，不直接上 24 V。
   - `GPI_COMMON`、GPI 极性、GPO 公共端全部保持“待现场确认”。
   - GPO 只允许接假负载或外部中间驱动电路，不直驱刹车线圈。
7. 对 Hall 线保持最小闭环不用、贴标绝缘；若要体检，只允许独立 5 V 限流测试 0/5 V 跳变。
8. 所有结果回填 `40_逐线验收记录表.md`，未闭合项继续保留在 `46_未闭环逐线缺口清单.md`。

## 6. GM1/EtherCAT 差异层

本节只处理 GM1 控制器和 EtherCAT 总线。DS-BVM 到电机侧仍按第 5 节共享底座执行。

### 6.1 携带工具

- Panasonic GM1 工程软件或可打开现场工程的电脑。
- PANATERM Lite for GM。
- ServoStudio。
- DS-BVM ESI/XML 文件。
- 屏蔽 Cat5e/Cat6 网线或厂家 EtherCAT 线。
- 万用表、相机。

### 6.2 操作

1. 确认 GM1 型号、供电、工程文件名和工程版本。
2. 在 GM1 工程里导入或核对 DS-BVM ESI/XML。
3. 用成品屏蔽网线连接：
   - GM1 EtherCAT 口 -> DS-BVM `ECAT IN` / `M11/J11 Input`。
   - 单轴时 DS-BVM `ECAT OUT` 先不接。
4. 上电后只做扫描和只读确认：
   - 扫描 DS-BVM 从站。
   - 记录从站名称、站号、状态、是否进入 OP。
   - 读取或监视 `0x6041` Statusword、`0x6061` Modes of operation display、`0x6064` Position actual value。
5. 未通过第 5 节共享底座运动前检查前，不写 `0x6040`，不 Servo On，不 PPM 小步。

### 6.3 预期结果

| 观察点 | 预期 |
|---|---|
| 从站扫描 | 能识别 DS-BVM，型号/站号可记录 |
| ESI/XML | 对象和 PDO 名称可被工程识别 |
| `0x6041` | 状态稳定，可解释报警或安全状态 |
| `0x6064` | 手转编码器或驱动器反馈变化连续 |

## 7. STM32H7/CANopen 差异层

本节只处理 STM32 主站、CAN 收发器和 CANopen 报文。DS-BVM、电机、编码器、刹车、STO 和电源仍按第 5 节共享底座执行。

### 7.1 携带工具

- STM32H743 板。
- ST-LINK 或板载调试器。
- STM32CubeProgrammer。
- USB-CAN 工具 UTC-T01 或等效 CAN 分析工具。
- CAN 分析软件。
- 万用表、示波器。
- 外接 CAN 收发器模块，现场已见模块标有 `3.3V/GND/CAN RX/CAN TX/CANL/CANH`，芯片疑似 VP230。
- 120 ohm 终端电阻、短双绞线、相机。

### 7.2 最小 CAN 接线

先确认 STM32 板上是否已有 CAN 收发器。STM32H7 的 FDCAN 引脚不能直接接 DS-BVM CANH/CANL，必须经过 CAN 收发器。

**2026-09-18 板级事实（公开资料，阿里云/正点原子与 RT-Thread BSP 文档）**：阿波罗 H743 底板**自带 TJA1050 CAN 收发器**（板载资源清单明列「1 路 CAN 接口，采用 TJA1050 芯片」）。对当前接线有两条直接后果：

1. **PA11/PA12 在板上是 USB 与 CAN 复用，出厂跳线默认给 USB。** 底板有一个「CAN/USB 选择接口」排针；要走路载 TJA1050，必须把跳线帽从 USB 侧改到 `CRX`/`CTX`（即收发器 RXD/TXD）侧。跳线不动就烧 CANopen 固件，PA12 的发送**不会到达任何收发器**。现场照片里板上可见 `CANH/CANL`、`CAN_TX/CAN_RX`、`PA12` 丝印，与上述一致。
2. **因此当前是否需要外接 VP230 模块取决于该跳线状态**，不取决于猜测。若跳线已改到 CAN 侧，可用板载 TJA1050；若仍是 USB 侧或不想动跳线，才用外接模块。两者只能选一个，不要把 PA11/PA12 同时接到板载收发器和外接模块。

终端电阻随之改变：板载 TJA1050 路径的终端在板上；外接 VP230 模块上有一颗 `121`（即 120 Ω）。无论走哪条，**断电测 CANH-CANL 仍按 §7.3 执行**——约 60 Ω 表示两端终端都在，约 120 Ω 表示只有一端。

| 起点 | 中间 | 终点 | 状态 |
|---|---|---|---|
| STM32 `PA12 / FDCAN1_TX` | 外接或板载 CAN 收发器 `TXD` / `CAN TX` | 不直接到 DS-BVM | 待现场确认 |
| STM32 `PA11 / FDCAN1_RX` | 外接或板载 CAN 收发器 `RXD` / `CAN RX` | 不直接到 DS-BVM | 待现场确认 |
| 底板 `CAN/USB 选择接口` 跳线 | 必须在 CAN 侧（`CRX`/`CTX`），不能停在 USB 侧 | 决定板载 TJA1050 是否可用 | 2026-09-18 公开资料确认存在，现场跳线位置待拍照 |
| STM32 3.3 V | 收发器 `3.3V` | 给逻辑侧供电 | 待现场确认模块供电要求 |
| STM32 GND | 收发器 `GND` | 与 CAN 参考地相关 | 待现场确认 |
| 收发器 `CANH` | 双绞线 | DS-BVM CAN J8/J9 Pin1 `HIGH` | 驱动器侧 pinout 已有较强证据，仍拍照复核 |
| 收发器 `CANL` | 双绞线 | DS-BVM CAN J8/J9 Pin2 `LOW` | 同上 |
| 收发器/CAN `GND` | 信号参考地 | DS-BVM CAN J8/J9 Pin3 `GND` | 待现场确认共地或隔离策略 |

驱动器侧按已确认事实记录：DS-BVM CAN 接口 J8/J9，Pin1=`HIGH`，Pin2=`LOW`，Pin3=`GND`；配件线色红=`HIGH`，红灰=`LOW`，蓝=`GND`。现场仍要拍接口、线色和端子方向，避免镜像误判。

### 7.3 共地与终端

1. 断电测 CANH-CANL 电阻。
   - 约 `60 ohm`：两端 120 ohm 终端都在。
   - 约 `120 ohm`：只有一端终端，另一端待补。
   - 开路、短路或异常：不继续上电。
2. 非隔离 CAN 收发器时，STM32/收发器 GND 与 DS-BVM CAN GND 需要信号参考。上电前先测两侧 GND 电位差；异常则暂停，改用隔离 USB-CAN 或隔离 CAN 收发器。
3. CANH/CANL 用双绞线，短支线，不和 U/V/W、刹车电源线捆在一起。

### 7.4 STM32 固件只读确认

1. ST-LINK/SWD 连接 `SWDIO`、`SWCLK`、`NRST`、`GND`、目标板电压参考。
2. 打开 STM32CubeProgrammer。
3. 选择 `ST-LINK`、接口 `SWD`，先 `Connect`。
4. 记录 `Device ID`、Flash Size、芯片型号识别结果。
5. 打开 `Option Bytes`，只读记录 RDP 状态；不改 Option Bytes。
6. 若 RDP 未锁，读取 Flash 并导出文件，记录文件名和校验和；若 RDP 锁定，只记录无法读取，不擦除、不降级保护。
7. 若接串口，记录串口输出和波特率；若接 CAN，只监听是否有 CANopen boot-up、heartbeat、NMT、SDO/PDO 行为。

判断原则：归档代码中出现 `fdcan_demo` 或 `FDCAN_MODE_EXTERNAL_LOOPBACK`，不能证明现场烧录固件就是最终 CANopen 主站。必须用当前板子的只读固件信息、串口输出和实测 CAN 报文判断。

### 7.5 分阶段 CANopen 只读验证

#### 阶段 1：物理层

> **进展修订（2026-08-01）**：CANH/CANL/GND 已通过 XCAN-USB 验证可通信；当前为 Node 1、1 Mbps。Windows-PCAN 已进一步完成 NMT、CiA 402 和固定 PPM `+5000/-5000 counts`，但该结果不替代终端电阻、CANH/CANL 静态电压或 STM32 物理层实测。

**携带工具**：万用表、示波器、USB-CAN、120 ohm 电阻、相机。  
**操作**：断电测终端；确认 CANH/CANL/GND；上电后看 CANH/CANL 静态电压和差分跳变；波特率优先从已知线索 `1 Mbps` 开始，再按软件自动探测或逐档记录。  
**预期结果**：终端合理，CANH/CANL 不短路，总线有稳定报文或静态电平可解释；否则不做 SDO。

#### 阶段 2：只读监听

**携带工具**：UTC-T01 USB-CAN、CAN 分析软件。  
**操作**：USB-CAN 并联到 CANH/CANL/GND；先不发 NMT/SDO/运动命令，只观察 boot-up、heartbeat、EMCY。重点看 `0x700 + nodeID` 和 `0x80 + nodeID`。  
**预期结果**：能看到节点上线或心跳，或能确认当前总线沉默；不能把总线沉默解释为设备坏，先查波特率、终端、节点供电和 DS-BVM CAN 参数。

注意：有些 USB-CAN 软件的“listen-only/silent”模式不会给 CAN 帧 ACK。如果总线上只有 DS-BVM 一个发送节点，再加一个纯静默监听器，可能看到错误帧、重复发送或沉默。现场“只读”的含义是**不主动发运动命令、不写对象**；是否使用 listen-only 还是 normal receive 模式，要记录清楚。若为了 ACK 使用 normal receive，也只能进入阶段 3 的 SDO 只读，仍禁止写 `0x6040` 或 PDO 映射。

#### 阶段 3：SDO 只读

**携带工具**：USB-CAN、CANopen SDO 工具或可发送 SDO 的分析软件。  
**操作**：在伺服未使能状态下，只读以下对象：

| 对象 | 用途 |
|---|---|
| `0x1000` | Device type |
| `0x1001` | Error register |
| `0x1017` | Producer heartbeat time |
| `0x1018` | Identity |
| `0x6041` | Statusword |
| `0x6061` | Modes of operation display |
| `0x6064` | Position actual value |

**预期结果**：对象能读，返回值稳定，状态字可解释。此阶段不写 `0x6040`，不写 PDO 映射，不发 Servo On。

SDO 只读帧模板如下，`nodeID` 必须用现场扫描/参数确认值，不可直接套用归档 `0x21`：

| 读对象 | 请求 COB-ID | 请求数据 8 字节 | 响应 COB-ID | 记录 |
|---|---|---|---|---|
| `0x1000:00` | `0x600 + nodeID` | `40 00 10 00 00 00 00 00` | `0x580 + nodeID` | Device type |
| `0x1001:00` | `0x600 + nodeID` | `40 01 10 00 00 00 00 00` | `0x580 + nodeID` | Error register |
| `0x1017:00` | `0x600 + nodeID` | `40 17 10 00 00 00 00 00` | `0x580 + nodeID` | Heartbeat time |
| `0x1018:01` | `0x600 + nodeID` | `40 18 10 01 00 00 00 00` | `0x580 + nodeID` | Vendor ID |
| `0x6041:00` | `0x600 + nodeID` | `40 41 60 00 00 00 00 00` | `0x580 + nodeID` | Statusword |
| `0x6061:00` | `0x600 + nodeID` | `40 61 60 00 00 00 00 00` | `0x580 + nodeID` | Mode display |
| `0x6064:00` | `0x600 + nodeID` | `40 64 60 00 00 00 00 00` | `0x580 + nodeID` | Actual position |

若返回 abort SDO 或没有响应，不继续尝试写对象；先记录请求帧、响应帧、波特率、节点号、驱动报警和电源状态。

#### 阶段 4：写参数前门槛

原则上只有第 5 节共享硬件底座通过、DS-BVM 参数已备份、刹车/STO/电机参数已闭合、机械防坠到位，才允许考虑写 CANopen 对象或进入运动验证。2026-08-01 Windows-PCAN 固定轨迹实验是在用户对当前现场条件逐项确认后执行的有界研究记录，不能用来自动放行后续不同路线或不同轨迹。

## 8. 运动前共享检查清单

| 检查项 | 检查方法 | 通过标准 | 未通过时 |
|---|---|---|---|
| 电机 U/V/W | 拍照、线标、三相电阻、对壳绝缘 | 三相近似一致，对壳无异常，线序有证据 | 不接主电 |
| 编码器 | 查 pinout、测 5 V、手转看 `0x6064` | 供电正确，位置连续变化 | 不 Servo On |
| 刹车 | 量白线电阻，限流 24 V 短时测试 | 通电释放、断电抱闸，电流合理，有防坠 | 不释放，不点动 |
| STO | 查手册/厂家，限流验证 J13 输入 | 有效极性和安全回路明确 | 不短接，不使能 |
| 24 V 电源 | 测 LRS-100-24 输出、电流余量、FG/0V | 电压和接地可解释 | 不上驱动主电 |
| CAN/EtherCAT | 只读扫描、监听、对象读取 | 通信稳定，但不作为运动放行 | 回到物理层排查 |

| 驱动参数 | 极对数、CPR、电流、反馈模式、限位 | 有厂家/图纸/手册或实测证据 | 不 Jog |
