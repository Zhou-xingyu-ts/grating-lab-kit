# 2026-08-09 STM32H743 仅 ST-LINK 下载与板上启动验证

**结论：`PASS_WITH_LIMITATIONS`（仅 STM32 板级 Gate 1）**

今天在用户明确授权下，只完成了“电脑 → USB → ST-LINK/SWD → STM32”的下载与启动验证。STM32 没有连接 CAN 收发器、DS-BVM、GM1、EtherCAT、编码器、电机、抱闸、STO 或任何驱动器侧线路；因此没有执行 CANopen 读写、NMT、PDO、SYNC、伺服使能或运动。

- STM32CubeProgrammer 及命令行均识别到：`STM32H7xx`、Device ID `0x450`、`Rev V`、Cortex-M7、2 MiB NVM、目标电压 3.12 V。

- 只读 Option Bytes 结果：RDP `0xAA`（Level 0），启动地址 `0x08000000`，未报告写保护；未改变任何 Option Bytes。
- 写入的固定 V9 Arm GNU 映像为 [MotionControllerRouteBV9FirmwareH743.hex](D:/清华/清华-科研横向/光栅尺运动控制调研/motion_acquisition/build/v9_offline_completion_20260809_15/arm-gnu/MotionControllerRouteBV9FirmwareH743.hex)，SHA-256：`F668ED25EF7D6599ADC8D82D22C9D32098EAA10B1463A2F6D9E5A36D50BAB9A2`。
- 写入地址 `0x08000000`，写入量 32.47 KiB；仅擦除了内部 Flash sector 0。工具返回 `Download verified successfully`，随后执行软件复位。

## 板上运行证据与限制

软件复位后，最初的普通 SWD 连接和 HotPlug 连接均报 `Unable to read device id from ROM table` / `ST-LINK DEV_CONNECT_ERR`。随后做了一个仅 SWD 的低频复查：命令请求 1 MHz，STM32CubeProgrammer 实际报告为 950 KHz。该频率下，HotPlug 仍报相同 `DEV_CONNECT_ERR`，没有修复。

同一实际 950 KHz 下，带 `reset=SWrst` 的 Normal 连接成功识别 `0x450`，并读取诊断区 `0x38000000` 的魔数 `0x4D433830`。这是软件复位后的单字诊断读取，不是稳定运行态调试附着成功，也不能改变 HotPlug 失败这一限制。

随后仅用 Under Reset 模式读取诊断区 `0x38000000`。读取到的结构魔数为 `0x4D433830`、版本 `3`、结构大小 `0x248`；`last_fault=0`，`real_hardware_access=0`、`device_write_capability=0`、板级映射可用性均为 `0`。调度计数为：scheduler 43,462、realtime 43,462、mainline 4,347、health 435、deadline misses 1。

结合固定映像 SHA-256、下载后校验成功记录和上述非零调度计数，可以确认锁定态 V9 运行时在该 STM32 上于复位后执行过。诊断区中保留了历史 V8 build 字符串，因此没有把该字符串作为 V9 的身份依据；身份依据是本次选定 HEX 的 SHA-256 和下载校验记录。

这仍不证明稳定的运行态调试连接，也不证明 FDCAN、CANopen、DS-BVM、GM1、EtherCAT、安全链路、实时性、精度或实机运动。本次复查没有连接或访问 CAN、驱动器或运动硬件。
