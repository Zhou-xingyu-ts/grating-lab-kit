# 实验室推进记录维护与同步规则

本文档用于规范 `60_实验室推进记录/` 与 `40/46/58/59` 之间的关系，避免重复、遗漏、结论外推和文档漂移。

## 1. 文件夹定位

`60_实验室推进记录/` 是每次现场实验、实验室推进、试接、试动、接口确认、异常现象和阶段性结论的完整过程记录目录。

它保存“实际做了什么、看到了什么、能推出什么、不能推出什么、下一步是什么”。它不替代现有主文档，也不作为单独的运动放行依据。

## 2. 与主文档的分工

| 文件/目录 | 职责 |
|---|---|
| `60_实验室推进记录/` | 完整过程记录、现场上下文、时间线、边界声明 |
| `40_逐线验收记录表.md` | 从实验中抽取出的可验收事实 |
| `46_未闭环逐线缺口清单.md` | 从实验中抽取出的未闭环事项和风险边界 |
| `58_现场实拍确认事实索引.md` | 截图、照片、手册页、参数备份等证据索引 |
| `59_现场检查与测量任务单.md` | 下一步任务、待补证据、现场检查状态 |

完整实验过程只写在 `60_实验室推进记录/` 中。`40/46/58/59` 只同步摘要、缺口、证据索引和任务状态，不重复完整过程。

## 3. 受控重复原则

同一实验事实可以出现在多个文件中，但必须是不同视角。

例如“X 轴无刹车电机低速 Jog 试动”：

- 在 `60` 中写完整过程；
- 在 `40` 中写可验收事实；
- 在 `46` 中写不能外推到 Z 轴和光栅尺闭环；
- 在 `58` 中登记截图；
- 在 `59` 中标记任务完成和待补证据。

禁止：

- 在多个文件中重复粘贴完整实验过程；
- 在摘要文件中写过长流水账；
- 在缺口文件中写成已放行；
- 在证据索引中写没有截图支持的事实；
- 在任务单中写成最终结论。

## 4. 单次实验记录流程

1. 先在 `60_实验室推进记录/` 新建一篇按日期命名的实验记录。
2. 在实验记录中写清楚目标、前置状态、操作、观察、可支持结论、不能推出结论、遗留问题。
3. 在日志末尾写“建议同步到主文档”。
4. 再根据日志内容同步到 `40/46/58/59`。
5. 同步时只提炼，不复制完整过程。
6. 同步后在日志中标注“已同步 / 部分同步 / 未同步”。

## 5. 命名规则

实验推进记录推荐命名格式：

`YYYY-MM-DD_对象_动作或主题.md`

例如：

- `2026-06-03_X轴无刹车电机_ServoStudio低速Jog试动.md`
- `2026-06-03_DS-BVM_EtherCAT_RJ45_to_Molex接口适配观察.md`
- `2026-06-03_DS-BVM_电机8pin编码器反馈只读观察.md`

如果同一天同一主题有多次记录，可使用：

- `2026-06-03_主题_A.md`
- `2026-06-03_主题_B.md`

也可以在文件名中加入更具体对象。

## 6. 每篇记录最低要求

每篇推进记录至少包含：

- 日期；
- 实验/推进对象；
- 控制方式；
- 实验前状态；
- 本次允许操作；
- 本次禁止操作；
- 实际操作过程；
- 现场观察与数据；
- 截图/照片证据；
- 可支持结论；
- 不能推出结论；
- 遗留问题；
- 建议同步到哪些主文档。

## 7. 结论边界规则

不得把局部实验结论外推到系统级结论。当前项目中尤其要区分：

- X 轴无刹车电机试动；
- Z 轴带刹车平台；
- 电机侧 8pin 编码器反馈；
- Renishaw 光栅尺 / Ri0040 反馈；
- Servo Studio / USB-COM 控制；
- GM1 / EtherCAT 控制；
- STM32 / CANopen 控制；
- 只读观察；
- 主动运动；
- 临时低速试动；
- 正式运动放行。

禁止外推示例：

- X 轴无刹车电机能 Jog，不代表 Z 轴带刹车平台可以运动；
- Servo Studio 能低速 Jog，不代表 GM1/EtherCAT 已控制 DS-BVM；
- 电机 8pin 编码器 Position 可见，不代表 Renishaw 光栅尺已接入；
- Motion 页面截图不等于 STO、刹车、限位、Home 已放行；
- 参数备份可读不等于现场接线或运动安全已验证。

## 8. 证据管理规则

- 截图、照片、手册页、参数备份、现场视频等证据，应在 `58_现场实拍确认事实索引.md` 中登记。
- `60` 中可以引用截图文件名，但不得虚构文件名。
- 文件名未整理时写“待补充文件名”。
- 截图事实只能支持截图能直接证明的内容。
- 不得把截图事实扩大为电气连续性、安全功能或运动放行结论。

## 9. 缺口同步规则

每次实验后必须检查是否需要更新 `46_未闭环逐线缺口清单.md`。

规则：

- 如果某项有进展，只能标为“部分进展”或“初步打通”，除非证据链完整闭环。
- 对于未验证的安全相关项，必须保留未闭环状态。
- 不能因为局部对象试动成功，就关闭系统级缺口。

## 10. 任务同步规则

每次实验后必须检查是否需要更新 `59_现场检查与测量任务单.md`。

规则：

- 已完成的任务要标记完成；
- 未完成但有进展的任务标记部分完成；
- 新发现的缺口要新增任务；
- 不要新增超出当前安全阶段的运动任务；
- 对 Z 轴、刹车、STO、限位、Home、光栅尺等必须保持独立任务。

## 11. 冲突处理规则

如果 `60` 与 `40/46/58/59` 出现不一致，应按以下顺序处理：

1. 优先查看原始截图、照片、手册页和参数备份。
2. 再查看对应日期的 `60_实验室推进记录/`。
3. 再修正 `40/46/58/59` 的摘要。
4. 不得直接删除旧记录，应通过补充说明或更正记录处理。
5. 对于安全边界冲突，默认采用更保守结论。

## 12. Codex 后续维护要求

- 每次修改前先只读检查入口链和相关文件。
- 先说明计划修改范围，再做最小范围修改。
- 不得擅自修改 `90_原始资料/`、`99_归档/`。
- 不得擅自修改 `39_上电前逐线放行矩阵.md`。
- 不得把实验记录写成运动放行。
- 不得补造截图名、参数值、接线结论。
- 修改后必须汇总：
  - 修改了哪些文件；
  - 新增了哪些事实；
  - 哪些只是部分进展；
  - 哪些仍未闭环；
  - 下一步建议补哪些证据。
