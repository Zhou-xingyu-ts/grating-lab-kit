# 时间与信号质量审计

## 1. 结论先行

14 份 CSV 的轮次和对象完整性良好，足以做低频趋势和 counts 域外部闭环描述；但命令事件没有进入同一时间合同，同轮对象也是顺序 SDO 读取而非同步快照。因此：

- 低频 demand→actual 描述可做；
- Servo Studio 命令纯延迟、对象间高频相位、内部环带宽和机械共振不可由现有数据识别；
- 任何模型都必须使用实际 `elapsed_s`，不能假定严格等间隔。

## 2. 五种时间概念必须分开

| 概念 | 当前定义 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| requested period | CLI `--period` / manifest `acquisition.period_s` | 主机计划的轮次周期 | 实际轮次、设备控制周期 |
| actual cadence | 相邻唯一 `sample_seq` 的 `elapsed_s` 差 | 主机记录的真实轮开始节拍 | 设备锁存时刻、同步快照 |
| processing capacity | `1 / mean_cycle_s` | 一轮对象读取工作段的平均吞吐上限 | 实际调度频率；195923 的 95.53 Hz 不等于实际 50 Hz |
| round timestamp | `read_once()` 在循环对象前调用一次 `Timebase.now()` | 一轮开始的主机观察时刻 | 每个对象的请求/响应完成时刻 |
| object acquisition order | manifest 列表顺序，源码逐对象 SDO upload | demand先于actual，actual先于error被读取 | 三对象同一设备时刻 |

## 4. 实际节拍、抖动和处理超时

| 配置 | 文件 | 实际轮次率 | dt 中位数 | dt P95 | dt 最大值 | dt 变异系数 | manifest工作段 deadline miss |
|---|---|---:|---:|---:|---:|---:|---:|
| 7对象，请求20 ms，运动/静止 | `195810`—`201224` 等 | 49.999—50.000 Hz | 20.021—20.026 ms | 20.209—20.295 ms | 20.458—20.904 ms | 0.78%—0.93% | 0 |
| 7对象，请求10 ms，静止 | `201548` | 98.620 Hz | 10.131 ms | 10.516 ms | 10.833 ms | 2.46% | 262/987 |
| 7对象，请求5 ms，静止 | `201745` | 101.624 Hz | 9.848 ms | 10.131 ms | 10.910 ms | 1.91% | 1017/1017 |
| 3对象，请求5 ms，静止/运动 | `201831`—`203414` | 199.204—199.953 Hz | 4.996—5.011 ms | 5.310—5.446 ms | 5.905—8.314 ms | 3.48%—4.74% | 3—53 |

`deadline_miss_count` 的源码定义是“对象读取工作段耗时大于目标周期”，并不是相邻轮次迟到次数。50 Hz 文件即使一半以上 dt 略大于 20 ms，也仍可通过后续短一点的间隔维持约 50 Hz；不能把浮点级/调度级轻微超出逐项写成硬实时丢周期。

对低频描述，50/200 Hz 组的平均节拍稳定；对高频相位、纯延迟或共振，3对象组最高 8.314 ms 的轮次间隔和对象内未知偏移已足以产生偏差。

## 5. 首尾、漂移和截断

- 原始首轮 wall time 比 manifest `start_time` 晚约 0.437—0.577 s；manifest `end_time` 比原始末轮晚约 1.176—1.219 s。这是会话建立/关闭边界，不能当作运动延迟。
- 原始 `elapsed_s` 跨度与计划持续时间基本一致：例如 30 s 文件跨度约 29.98—30.00 s。
- 每份日志的 wall-clock 首末跨度与 monotonic/elapsed 跨度之差在 -0.219—1.291 ms，符合 wall time 只保存到毫秒的量化；本批文件未见主机两种时间表示的可见漂移。
- `202749` 的第三次返回和 `202943` 的返回被采集窗口截断。截断是运动内容覆盖不完整，不是 CSV 行缺失。

## 6. demand、actual、following error 代数关系

若三对象是同步快照且定义为 `following_error = demand - actual`，残差应严格为 0。实测：

| 文件组 | 精确相等比例 | `error-(demand-actual)` 范围 | 解释 |
|---|---:|---:|---|
| 静止3对象/7对象 | 通常 100% | 0 | 信号不变时顺序偏移不可见 |
| `195923` | 97.13% | -7…+7 counts | 动态中对象依次读取 |
| `200718` | 90.53% | -7…+9 counts | 同上 |
| `201224` | 91.83% | -9…+8 counts | 同上 |
| `202323` | 88.13% | -9…+8 counts | 200 Hz仍非同步快照 |
| `202749` | 74.55% | -9…+9 counts | 动态样本更多，顺序偏移更明显 |
| `203414` | 94.15% | -9…+9 counts | 同上 |

残差均值接近 0，且静止时严格闭合，强支持 `demand-actual` 的基本符号关系；动态偏差不能当成第四种物理误差，应首先解释为轮内顺序采集。

## 7. 状态字和错误码

- 具有 `error_code` 的 8 份 7对象/4对象日志中，`0x603F` 全程为 0。
- `195810` 捕获状态字 `0x0240 → 0x0021 → 0x0033 → 0x0437`，与实验记录的使能过程一致。
- 动态文件还出现 `0x1037/0x1437` 等目标/运动相关位组合；本审计不越过手册证据去重新命名每个位。
- 3对象 200 Hz 文件没有状态字和错误码，因此只能由并行界面观察/实验记录补充，不能证明该文件内部每一时刻的状态。

## 8. 命令时刻与运动起点

- Servo Studio 命令点击/提交时刻没有记录在 CSV 或 manifest 中，不能确定 PC 命令延迟。
- 可以确定的只是 `position_demand` 首次变化的“观测起点”。
- actual 相对该观测起点跨过 2 counts 的表观时间约 40—105 ms；该数字同时包含内部轨迹发生器、闭环响应、阈值选择和轮内顺序读取，不是纯延迟估计。

## 9. 对建模的裁决

| 用途 | 裁决 |
|---|---|
| counts域低频稳态/慢轨迹描述 | 可用，必须保留实际时间戳 |
| 同一文件内方向/阶段比较 | 可用，但要固定窗口并报告采样不确定性 |
| 跨独立文件留出 | G4可做一次，其他组不足或不平衡 |
| Servo Studio命令纯延迟 | `BLOCKED_BY_TIME_SEMANTICS` |
| 三对象同步状态空间辨识 | 不支持；无同步快照 |
| 内部环带宽、机械共振、1 ms动态 | 不支持 |
| 物理长度、速度和绝对精度 | `BLOCKED_BY_CALIBRATION`，严格结论限 counts 域 |
