# 第一层：导师汇报版

## 1. 课题目标与定位

**课题暂定方向**：基于自研高精密光栅尺反馈的开源化闭环控制精密位移运动台

**课题定位**：精密运动控制 + 嵌入式实时控制 + 仪器科学，属于机电一体化系统方向（而非纯传感器方向或纯控制理论方向）。

**第一阶段核心目标**：
- **小行程（10-50 mm）条件下实现重复定位精度 ≤ 0.5 μm**
- 自研光栅尺成功接入闭环控制系统，作为主位置反馈
- 全系统通信协议、控制接口、数据接口公开可审计
- 全过程运动数据可记录、可追溯、可离线分析

**暂不承诺的内容**：
- 全行程绝对定位精度 ≤ 0.5 μm（需要全行程标定和更强温控）
- 300 mm 长行程（热膨胀、导轨误差、阿贝误差显著增大）
- 高速运动下的跟踪精度（先解决静态/低速重复精度）

### 核心科学问题与工程问题

**核心科学问题**：
- 自研光栅尺的反馈信号如何以确定性的低延迟、低抖动方式进入实时闭环控制链路？
- 开放控制架构如何在不依赖闭源专用运动控制器的条件下，实现与商业闭环方案可比的重复定位精度？

**核心工程问题**：
- 如何设计光栅尺信号采集→细分→时间戳→控制周期同步的工程链路？
- 如何用激光干涉仪等手段证明系统确实达到了 ≤ 0.5 μm 的重复定位精度？
- 如何设计数据字典和存储方案，使全过程运动数据可记录、可分析、可复现？

**自研光栅尺反馈 vs 商业光栅尺反馈——创新性差异**：

| 维度 | 商业光栅尺（如 Renishaw TONiC） | 自研光栅尺（本课题） |
|------|-------------------------------|-------------------|
| 信号链可见性 | 黑盒。sin/cos → 细分 → 正交输出，内部不可见 | 白盒。从光电信号到细分到输出，全程可控 |
| 数据可记录性 | 仅能拿到位置值（ABZ 或串行协议），无法记录原始信号 | 可记录原始 sin/cos 幅值、相位、信号质量 |
| 细分算法可控性 | 固定 ASIC（如 Renishaw 定制芯片） | FPGA 可重配置（精度/速度折衷可调） |
| 时间戳可控性 | 受限于商业接口协议（EnDat/BiSS 的传播延迟不可控） | 可自行设计低延迟同步采样时间戳 |
| 研究价值 | "买来用"——适合工程验证 | "自研接入"——适合硕士课题创新 |

## 3. 为什么需要开放式控制架构

**闭源运动控制器的核心问题**（以 Aerotech A3200、ACS SPiiPlus、Galil DMC 为例）：

| 问题 | 影响 |
|------|------|
| 控制算法黑盒 | PID 参数可见，但 PID 内部实现不可见；前馈、滤波、陷波器结构无法修改 |
| 数据接口封闭 | 位置/速度/电流数据通常不外流，或需付费 SDK 才能导出 |
| 协议私有 | ACS 的 SPiiPlus 协议、Aerotech 的 A3200 ASCII 协议为闭源；不同品牌互不兼容 |
| 可复现性差 | 五年后设备换代，旧控制器停产，数据格式无法解析 |
| 论文表达受限 | 无法说清"闭环到底是怎么工作的"——导师可能质疑 |

**本课题与闭源方案的对比**：

| 需求 | 闭源方案 | 本课题方案（路线 B） |
|------|---------|-------------------|
| 高精度闭环 | ✅ 商业方案可做到 | ✅ 通过开放 RT 控制器 + 商业驱动实现 |
| 完全自主闭环算法 | ❌ 无法修改 | ✅ 位置外环自主实现 |
| 全过程运动数据 | ❌ 受限或需付费 | ✅ 自定义数据字典 |
| 协议/接口开放 | ❌ 私有 | ✅ EtherCAT CoE（标准）+ 自定义监控协议 |
| 5 年后可复现 | ❌ 依赖特定硬件/FW 版本 | ✅ 全栈开源，可重建 |
| 导师认可度 | 低（"就是买来拼的"） | 高（"核心环节自己做的"） |

**核心设计原则**：
- 位置闭环在 RT Linux 上自主实现（可审计、可修改、可论文表达）
- 商业伺服驱动器仅工作在速度模式或电流模式（不承担位置闭环和轨迹规划）
- 光栅尺信号链自主可控（从光电信号到细分后的位置值，全程可记录）
- 所有数据接口公开（EtherCAT CoE 标准 + 自研监控协议）

## 5. 三条技术路线对比

| 维度 | 路线 A：低成本快速验证 | 路线 B：硕士论文推荐 | 路线 C：高性能高风险 |
|------|----------------------|-------------------|-------------------|
| **目标** | 证明"自研光栅尺可进闭环" | 重复定位精度 ≤ 0.5 μm | 最高带宽、最高自研程度 |
| **控制器** | STM32H7 / LinuxCNC (x86) | RT Linux + IgH EtherCAT 主站 (x86) | Zynq SoC (FPGA+ARM) |
| **细分器** | MCU 计数器 / A/B 正交解码 | FPGA (CORDIC + Heydemann) | FPGA (CORDIC + 在线补偿) |
| **通信协议** | 串口 / 自定义 SPI | EtherCAT CoE (标准) + 自定义监控 | EtherCAT (FPGA MAC) |
| **驱动器** | 步进驱动 (脉冲) / 伺服 (脉冲模式) | 商业伺服 (速度/电流模式, CiA 402) | 自研电流环驱动 / 直线电机驱动 |
| **电机** | 步进电机 / 低成本伺服 | 伺服电机 (交流伺服) | 无铁芯直线电机 |
| **位移台** | 交叉滚柱 + 精密丝杠（C5级） | 交叉滚柱 + C1/C3 预压丝杠 | 空气轴承 + 直线电机 |
| **控制周期** | ~1 ms | 250 μs - 1 ms | ≤ 100 μs |
| **预期重复精度** | ~2-5 μm（先跑通链路） | ≤ 0.5 μm（经过标定和调优） | < 0.1 μm（理想条件） |
| **硬件成本** | < 5,000 RMB | 1-3 万 RMB | 5-10 万+ RMB |
| **开发周期** | 2-3 个月 | 6-9 个月 | 12-18 个月 |
| **硕士独立完成风险** | 低 | 中等 | 高 |
| **适合阶段** | 研一下快速原型 | 研二论文主线 | 后续深造/博士 |

## 6. 为什么主推路线 B

**路线 B 的核心论证**：

1. **精度可达到**：商业 C1 级丝杠 + 预压双螺母 + 0.1 μm 级光栅尺反馈全闭环，双向重复精度 ≤ 0.5 μm 是工程上可实现的（参考：Aerotech PRO115LM 为 ±0.4 μm，PI L-511 为 ±0.15 μm）。

2. **开放程度足以说服导师**：
   - 位置外环在 LinuxCNC/IgH 上自主实现（核心闭环算法自己写）
   - 商业驱动器仅工作在速度/电流模式，不承担位置闭环——澄清"没有用闭源运动控制器"
   - 光栅尺信号链（读数头 → FPGA 细分 → 位置反馈）自主实现
   - EtherCAT CoE + CiA 402 是公开国际标准（IEC 61158），不是私有协议

3. **硕士可行**：LinuxCNC + PREEMPT_RT 社区成熟，IgH EtherCAT 主站有中文教程，Mesa FPGA 卡或自制细分板有开源参考。6-9 个月可完成搭建→调试→验证→论文写作。

4. **论文能收敛**：有对比实验、有定量指标、有数据记录、有创新点可写。

**为什么不主推路线 A？**
- 路线 A 精度太低（2-5 μm），论文写作时缺乏"挑战性"
- 导师可能认为"没有体现自研光栅尺的精密能力"

**为什么不主推路线 C？**
- Zynq + 直线电机 + 自研驱动 = FPGA 逻辑 + ARM Linux BSP + 电力电子 + 电机控制 四线并行
- 一个硕士 6-9 个月内难以独立完成
- 调试困难（直线电机失稳即撞机）
- 经费高（无铁芯直线电机 + 空气轴承 ≈ 5-10 万 起步）

## 7. 0.5 μm 重复定位精度可行性（按行程分级）

**严谨表述**：
> 第一阶段目标是在小行程（10-50 mm）条件下实现 **重复定位精度 ≤ 0.5 μm**。暂不承诺全行程绝对定位精度 ≤ 0.5 μm。

| 行程范围 | 重复定位 ≤ 0.5 μm 难度 | 主要限制因素 | 建议策略 |
|---------|----------------------|------------|---------|
| 10-25 mm | 中等 | 摩擦迟滞、光栅尺 SDE | 精密丝杠/C1级 + 预压 + 全闭环 |
| 50 mm | 中等偏高 | 同上 + 丝杠累积误差 | 同上 + 误差映射 |
| 100 mm | 偏高 | 丝杠热膨胀、导轨角摆 → 阿贝误差 | 需要低 CTE 光栅尺 + 温度补偿 |
| 300 mm | 高 | 热膨胀主导（钢：~3.6 μm/°C/300mm）、导轨长程误差 | **不在第一阶段承诺** |

**重复定位精度专用误差预算**（小行程 25 mm，路线 B 配置）：

| 误差源 | 是否影响重复精度 | 典型量级（RMS） | RSS 分量² | 控制手段 |
|--------|:----:|--------|--------|---------|
| 光栅尺刻度误差 | ❌ 共模抵消 | 0 | 0 | — |
| 导轨直线度/角摆 | ❌ 共模抵消 | 0 | 0 | — |
| 余弦安装误差 | ❌ 共模抵消 | 0 | 0 | — |
| **细分误差 (SDE)** | ✅ | ±30-80 nm | 0.0025-0.0064 | Heydemann 在线校正 |
| **光栅尺信号噪声** | ✅ | ±5-20 nm RMS | 0.0000-0.0004 | 低噪声放大、差分传输 |
| **摩擦迟滞** | ✅ **#1** | 50-300 nm | 0.0025-0.0900 | 预压双螺母 / 直线电机 |
| **反向间隙（机械）** | ✅ | 0-50 nm | 0.0000-0.0025 | 预压消除 / 软件补偿残余 |
| **伺服周期抖动** | ✅ | ≤ 20 μs @ RT | ~1 nm | PREEMPT_RT + CPU 隔离 |
| **短期温漂（1 min）** | ✅ | < 50 nm | 0.0025 | 实验室空调 ±1°C |
| **结构微振动** | ✅ | 10-30 nm | 0.0001-0.0009 | 光学平台 / 橡胶隔振 |
| **驱动器电流噪声** | ✅ | ~5-10 nm | 0.0000-0.0001 | 商业驱动本底满足 |
| RSS 合成（悲观情况） | — | — | **~0.341 μm** | ≤ 0.5 μm ✅ |
| RSS 合成（乐观情况） | — | — | **~0.088 μm** | ≤ 0.5 μm ✅ |

**结论**：在合理设计下（SDE < ±50 nm，摩擦迟滞 < 100 nm，温控 ±1°C），小行程重复定位 ≤ 0.5 μm **可在 RSS 合成后留有裕量**。最大的单项风险是摩擦迟滞——它直接决定了双向重复精度的下限。

## 8. 开放协议边界与闭源风险评估

### "开放"不等于"都选择开源"——三层划分

```
                          ┌─────────────────────┐
          监控/数据层      │  可任意选（不影响精度）│
         (上位机+存储)     │  OPC UA / TCP / ROS 2 │
                          └─────────┬───────────┘
                                    │
                          ┌─────────┴───────────┐
          控制层（实时）   │  必须开放/标准协议   │
         (位置外环+轨迹)   │  EtherCAT CoE (IEC)  │
                          │  或自定义 RT-Ethernet │
                          └─────────┬───────────┘
                                    │
                          ┌─────────┴───────────┐
          执行层（机电）   │  可用商业硬件        │
         (驱动+电机+导轨)  │  但接口必须标准/公开  │
                          │  CiA 402 (CANopen DS402)│
                          └─────────────────────┘
```

### 闭源风险评估

| 组件 | 闭源程度 | 对课题影响 | 是否可接受 |
|------|---------|----------|:----:|
| 商业伺服驱动器（速度模式） | 驱动内部 DSP 闭源 | 不承担位置闭环，不影响核心创新 | ✅ 可接受 |
| 商业伺服驱动器（位置模式/CiA 402 CSP） | 同上 | 需要论证"位置外环仍由自己实现" | ⚠️ 需说明 |
| EtherCAT 从站芯片 (LAN9252/ET1100) | ASIC 硬件闭源 | 协议标准公开 (IEC 61158)，任何人可实现 | ✅ 可接受 |
| FPGA 开发工具 (Vivado) | 工具闭源，生成的 bitstream 可逆向 | 芯片行为公开 | ✅ 可接受 |
| 商业直线导轨/丝杠 | 机械闭源 | 机械部件，与"控制开放"无关 | ✅ 可接受 |
| 闭源运动控制器 (如 ACS/Galil) | **全黑盒** | 核心闭环不可见——**不可接受** | ❌ 不可接受 |

### 导师可能的追问及回答

**Q1**："你用了商业伺服驱动器，这不还是闭源的吗？"

**A1**：驱动器内部的速度环和电流环是闭源的，但这个层次的闭源不影响课题创新性——因为：
- 速度环/电流环的感知-执行延迟是微秒级的，即使开源自研，替换进去后系统的可观测性也没有实质提升
- 课题的核心创新在于"自研光栅尺反馈进入位置外环"，这是决定系统精度的主反馈链路
- 类比：用商业 ADC 芯片做数据采集 ≠ "你用闭源数据采集卡"——关键看信号链路的核心环节和决策点在哪里

**Q2**："EtherCAT 是不是也是 Beckhoff 的私有技术？"

**A2**：EtherCAT 是公开国际标准（IEC 61158 Type 12），有开源的主站实现（IgH, SOEM），有公开的从站芯片（LAN9252, AX58100），任何人不需 Beckhoff 授权即可实现。这与"只有 Beckhoff 的 TwinCAT 才能用 EtherCAT"是两回事。

## 11. 明确结论

1. **课题成立**：自研光栅尺作为主反馈 + 开放控制架构 + 全过程数据记录，在技术上有增量、在工程上可落地、在论文上有可表达空间。

2. **主推路线 B**：RT Linux + IgH EtherCAT + CiA 402 商业伺服（速度/电流模式）+ FPGA 细分板。

3. **第一阶段可承诺**：小行程（10-50 mm）重复定位精度 ≤ 0.5 μm（经激光干涉仪验证）。

4. **不得承诺**：全行程绝对定位精度 ≤ 0.5 μm；300 mm 行程精度。

5. **三个核心创新**：(a) 自研光栅尺全信号链接入闭环；(b) 开放 RT 控制器替代闭源运动控制器；(c) 全过程运动数据可追溯。

6. **导师追问应对**：商业驱动做执行层 ≠ 用了闭源运动控制器；EtherCAT 是公开国际标准 ≠ Beckhoff 私有技术。

7. **论文主线**："基于自研精密光栅尺反馈的开放式闭环控制方法及其在精密定位中的实验验证"。

8. **下一步**：确认激光干涉仪获取方案 → 采购 FPGA 开发板 + 低成本伺服驱动 + 小行程位移台 → Phase 1 搭建。

### 核心科学问题 vs 核心工程问题

### 核心科学问题（偏学术表达）

1. **开放控制架构下的精密闭环问题**：在不依赖闭源专用运动控制器的条件下，如何设计实时控制架构使自研光栅尺反馈能以确定性低延迟、低抖动方式进入闭环，并达到与商业闭源方案可比拟的重复定位精度？

2. **多源误差对重复定位精度的贡献分离问题**：在自研光栅尺 + 开放控制 + 机械位移台的多级链路中，如何识别和定量评估光栅尺细分误差、摩擦迟滞、伺服抖动、短期温漂各自对重复定位精度的独立贡献？

### 核心工程问题（偏落地表达）

1. 自研光栅尺信号链路：从光电信号 → 模拟 sin/cos → ADC → 数字校正 → 细分 → 时间戳 → 反馈接口的完整实现。
2. 开放控制替代证明：如何通过对比实验（半闭环 vs 全闭环、自研反馈 vs 商业编码器）证明"开放架构不牺牲精度"。
3. 数据可追溯性实现：如何设计数据字典和存储方案，使全过程运动数据可记录、可离线分析、可复现。

## 三、创新性论证

### 七维度分析

| 维度 | 创新程度 | 论证 |
|------|:------:|------|
| 1. 自研光栅尺作为主位置反馈 | **强** | 区别于所有"买商业光栅尺 + 买商业控制器"的常规做法。信号链全透明。 |

### 创新点分级与推荐组合

**★★★★★ 强创新点（必须作为论文主线）**：
- **自研光栅尺全信号链接入闭环**：从原始光电信号到控制器中可用的位置反馈值，全程自主实现且数据可达。这是本课题区别于所有"买传感器 + 买控制器"方案的根本差异。
- **开放架构实现非亚微米重复定位精度**：证明"不用闭源运动控制器也能做到 ≤ 0.5 μm"。

**★★★ 中等创新点（建议作为论文支撑）**：
- 全过程运动数据字典设计与自研光栅尺原始信号记录
- 半闭环/全闭环/多反馈源对比实验方法论

**★ 不建议作为主创新点的内容**：
- 控制算法理论创新（摩擦模型、自适应控制等）
- 光栅尺光学/制造创新（属于课题组传感器方向，不是你的增量）

### 为什么这些方案不适合作为 0.5 μm 级闭环控制主链路？

| 方案 | 不适合的原因 |
|------|------------|
| CANopen | 1 Mbps 带宽限制 → 最小伺服周期 ~500 μs → 控制带宽不足亚微米级 |
| ROS 2 | DDS 无硬实时保障 → >100 Hz 就不稳定 → 不适合做位置闭环 |
| Modbus TCP | 无时间同步、非确定性延迟 → 误差 5-50 μm 级别 |
| OPC UA | 设计目标是工厂监控而非实时控制 → 延迟在 ms-s 级别 |
| 自定义 TCP/UDP | 无分布式时钟 → 多轴同步和采样时间戳都无法保证 |

### 三层架构分层

```
┌─────────────────────────────────────────────┐
│  第三层：监控与数据层（非实时）               │
│  推荐方案：OPC UA (open62541) / TCP-JSON     │
│  + HDF5 / SQLite 本地存储                    │
│  + Grafana / Plotly Dash 可视化              │
│  可替换：ROS 2 (仅用于非实时数据分发)         │
├─────────────────────────────────────────────┤
│  第二层：控制层（硬实时）                     │
│  推荐方案A：LinuxCNC + PREEMPT_RT (Mesa FPGA) │
│  推荐方案B：IgH EtherCAT Master + PREEMPT_RT │
│  → 两者均为开源 + 实时 + 可审计              │
│  → LinuxCNC+Mesa：更简单，适合单轴           │
│  → IgH EtherCAT：更灵活，适合多轴/商业驱动    │
├─────────────────────────────────────────────┤
│  第一层：执行层（机电）                       │
│  伺服驱动 + 电机 + 位移台                     │
│  驱动通信协议：EtherCAT CoE / CiA 402        │
│  光栅尺反馈：自研 FPGA 细分 → EtherCAT / 直连 │
└─────────────────────────────────────────────┘
```

### 为什么不混 Mesa 和 EtherCAT？

- **LinuxCNC + Mesa**：信号走 FPGA 编码器接口（ABZ/SPI），Mesa 通过 PCIe/以太网直连主机，不经过现场总线。适合单轴、简单架构。
- **LinuxCNC + IgH EtherCAT**：所有设备（驱动、IO、编码器）挂 EtherCAT 总线，由 IgH 主站统一管理。支持 DC 同步 < 100 ns。适合多轴、需要灵活扩展的系统。

两条链路的分界点在**编码器如何接入控制器**——不能混在一起说"差不多"。在论文和方案中必须明确选择其一。

| **光栅尺信号采集** | MCU 正交解码 (ABZ) + 硬件计数器 | 如果自研光栅尺可输出 ABZ；先在 MCU/FPGA 做计数 |
| **驱动器** | 步进驱动 (TB6600/DM542) 以脉冲+方向模式，或低成本伺服 (ODrive/SimpleFOC) | 脉冲模式简单，可直接由控制器 PWM 生成 |
| **电机** | NEMA23 步进 / 60-200W 交流伺服 | 低成本 (< ¥500) |
| **位移台** | 交叉滚柱导轨 + C5 滚珠丝杠 (如 Hiwin KK 模组) | ¥1,000-2,000 |
| **通信协议** | 串口 / USB / 自定义 SPI | 最简单 |
| **控制周期** | 1-5 ms | 受限于步进响应和 MCU 算力 |
| **上位机** | Python + pySerial / LinuxCNC GUI | 用于发指令、记录数据 |
| **数据记录** | CSV (串口日志 → pandas 分析) | 研一阶段足够 |
| **预期重复精度** | 2-5 μm | 受限于步进开环、丝杠精度、无严格温控 |
| **硬件成本** | < ¥5,000 | |
| **开发周期** | 2-3 个月 | |

**风险点**：
- 步进电机的丢步 + 无位置反馈（除非光栅尺反馈进入闭环）
- ODrive/SimpleFOC 的 ABZ 接口带宽和抗噪能力可能不足
- 仅验证"能闭环"，对 0.5 μm 精度的支撑非常有限

### 路线 B：硕士论文推荐路线（Phase 1→2→3 主线）

**目标**：小行程（10-50 mm）重复定位精度 ≤ 0.5 μm，全信号链自主实现。

| 子系统 | 选型 | 理由 |
|--------|------|------|
| **实时控制器** | x86 PC (i5/i7) + PREEMPT_RT 内核 + IgH EtherCAT Master | 开源、社区成熟；4-8 周可完成配置 |
| **FPGA 细分板** | Xilinx Artix-7 / Lattice ECP5 开发板 | 实现 12-14 bit ADC 采样 + Heydemann 椭圆校正 + 反正切细分 (CORDIC/atan2) |
| **细分器替代方案** | iC-Haus iC-NQE (4096×) 或 iC-NV (5×/10×/16×) | 如 FPGA 开发超期，先用商业插值芯片跑通 |
| **伺服驱动** | Delta ASDA-A3-E / Leadshine ELP (EtherCAT, CiA 402) | 支持速度模式、电流模式；已知 IgH 兼容 |
| **电机** | 400W 交流伺服（如 Delta ECM-B3） | 带 20-bit 电机编码器（用于速度内环） |
| **位移台** | 交叉滚柱导轨 + C3 或 C1 预压双螺母滚珠丝杠 | 如 Griffin LNS-BS-50 (50 mm 行程, ¥2,000-4,000) |
| **光栅尺** | 课题组自研光栅尺 + 自研读数头 | 本课题核心 |
| **控制周期** | 250 μs - 1 ms (EtherCAT) | IgH 主站 ≤ 250 μs 稳定，DC 同步 < 1 μs |
| **反馈链路** | 光栅尺 → 自研读数头 → FPGA 细分 (1000×) → 20 nm 位置值 → EtherCAT 从站 / 直接 PCIe → IgH 主站 → LinuxCNC 位置外环 |
| **位置闭环方式** | **LinuxCNC 位置外环** → 速度指令 → EtherCAT → 伺服驱动速度/电流环 → 电机 |
| **上位机** | LinuxCNC GUI / Python + HAL binding / Probe Basic |
| **数据记录** | HDF5/PyTables (二进制高效) + CSV 导出 |
| **预期重复精度** | ≤ 0.5 μm（经激光干涉仪验证） |
| **硬件成本** | ¥10,000-30,000（不含激光干涉仪） |
| **开发周期** | 6-9 个月 |

**为什么这条路线最适合硕士课题？**

1. **核心闭环自己实现**：位置外环在 LinuxCNC (GPLv2, 开源) 上自主实现。商业伺服驱动仅工作在速度模式（0x6060=3, Profile Velocity）或电流模式（0x6060=1, Torque Profile），不承担位置闭环和轨迹规划。导师追问时可以准确回答："驱动器只负责速度环，位置环是我们自己写的。"

2. **光栅尺反馈链路自主**：从读数头到 FPGA 细分到位置值反馈，全程自主实现。论文可以详细描述信号链设计。

3. **精度可达到且有裕量**：C3 级丝杠 + 预压双螺母 + 光栅尺全闭环 → 双向重复精度 ≤ 0.5 μm 是商业可达到的指标（参考：Aerotech PRO115LM ±0.4 μm）。

4. **实验对比充分**：可做 (a) 半闭环 vs 全闭环对比；(b) 不同细分倍数对比；(c) 不同前馈策略对比——论文内容充实。

### 路线 C：高性能高风险路线

**目标**：最高带宽、最高自研程度——但**不推荐作为第一阶段主线**。

| 子系统 | 选型 | 风险 |
|--------|------|------|
| **实时控制器** | Xilinx Zynq-7000 / Zynq UltraScale+ | **高**：需 FPGA 逻辑 + ARM Linux BSP 并行开发 |
| **细分 + 控制** | FPGA 细分 → ARM 控制闭环（单芯片） | **高**：FPGA-ARM 数据交互的延迟和带宽需精心设计 |
| **电机驱动** | 自研 IGBT/MOSFET 逆变器 + FOC | **极高**：电力电子 + 电机控制 + 安全保护 |
| **电机** | 无铁芯直线电机 (如 Akribis AUM, PI) | **中高**：成本高，调试需谨慎（失稳即撞机） |
| **位移台** | 空气轴承导轨 | **高**：需气源、超净环境、精密装配 |
| **控制周期** | ≤ 100 μs | **中高**：对实时系统要求极高 |
| **总成本** | ¥50,000-100,000+ | |
| **开发周期** | 12-18 个月 | |

**为什么不适合硕士独立完成？**
- 需要同时精通 FPGA 逻辑设计 + ARM Linux 驱动开发 + 电力电子 + 电机控制
- 任何一个子系统出问题都可能导致整个平台无法运行
- 调试周期不可控（电机失稳、散热、EMI……）
- 经费高（仅无铁芯直线电机 + 空气轴承就可能超过 ¥5 万）

**建议**：路线 C 可作为"未来展望"在论文最后一章提及。如果要走 C 路线，建议至少有一个硬件经验丰富的合作者，或推迟到博一再做。

## 六、"核心闭环自己实现"的准确定义

### 三种模式对比

| 模式 | 位置环在哪里 | 速度环在哪里 | 电流环在哪里 | 课题对"自己实现"的程度 |
|------|------------|------------|------------|:----:|
| 模式 1：全黑盒 | 商业闭源控制器 | 商业闭源控制器 | 商业驱动器内置 | ❌ 0% —— 导师不可接受 |
| **模式 2：位置外环自主** | **RT Linux/LinuxCNC (开源自研)** | **商业伺服驱动器（速度模式）** | **商业驱动器内置** | **✅ ~70% —— 硕士论文主推** |
| 模式 3：全自研 | RT Linux / FPGA（自研） | FPGA / MCU FOC（自研） | FPGA / 驱动芯片（自研） | ✅ 100% —— 硕士阶段风险过高 |

### 推荐：模式 2

**表述建议**（用于导师汇报和论文）：

> 本课题采用"位置外环自主、内环执行层商业驱动"的开放式控制架构：
> - **自研光栅尺**作为外部直接位置反馈，由自研读数头和 FPGA 细分器处理后，进入开放式实时控制器；
> - **开放式实时控制器**（LinuxCNC / RT Linux + IgH EtherCAT）实现**位置外环闭环控制**（PID + 速度/加速度前馈），承担轨迹规划和全闭环控制决策；
> - **商业伺服驱动器**仅工作在速度模式或电流模式，负责速度内环和电流环，**不承担核心位置闭环和轨迹规划功能**；
> - 位置指令从开放控制器通过 EtherCAT CoE（标准公开协议）下发至驱动器；
> - 全过程控制数据（指令位置、反馈位置、跟随误差、控制输出等）均可记录和审计。

### 为什么模式 2 不是"打擦边球"

- 速度环/电流环的感知-执行延迟是 μs 级的（~62.5 μs @ 16 kHz PWM），这部分如果自己重做，感知层面没有实质增益——因为瓶颈在电机电感时间常数（0.2-5 ms）。
- 位置外环才是决定系统精度的主反馈链路，而且也是运动学规划、误差补偿、模型预测等"论文可写"的算法所在层。
- 等价类比：你用商业 ADC 芯片做数据采集 → 不意味着"你用了闭源数据采集卡"。关键看你控制的决策点在哪里。

## 七、0.5 μm 重复定位精度详细可行性分析

### 7.1 按行程分级

| 行程 | 难度 | 机理 |
|------|:----:|------|
| 10-25 mm | 中等 | 丝杠累积误差 < 1 μm/25mm (C3)；摩擦迟滞 50-200 nm；光栅尺 SDE ±30-80 nm |
| 50 mm | 中等偏高 | 丝杠累积误差 ~2 μm/50mm (C3)；摩擦热开始累积 |
| 100 mm | 偏高 | 丝杠热膨胀开始显现（钢：~1.2 μm/°C/100mm）；导轨角摆 × 阿贝偏移 |
| 300 mm | 高 | 热膨胀主导（钢：~3.6 μm/°C/300mm）；导轨长程误差；不建议第一阶段承诺 |

### 7.2 光栅尺反馈分辨率最低要求

编码器分辨率经验法则：≥ 5-10 倍于目标重复精度。

| 法则 | 分辨率要求 | 推荐 |
|------|----------|------|
| 5 倍 | ≤ 0.10 μm (100 nm) | 最低可接受 |
| 10 倍 | ≤ 0.05 μm (50 nm) | **推荐** |

以 20 μm 光栅周期为例：分辨率 50 nm → 插值倍数 400×。在 12-bit ADC + Heydemann 校正下，400× 插值保守可达。

### 7.3 光栅尺 SDE 需要控制的量级

SDE 不影响重复精度中的"同方向同位置"分量，但影响"不同方向同位置"分量（因为 Lissajous 相位可能不同）。建议 SDE ≤ 重复精度 / 3 ≈ **≤ 150 nm**。

但考虑保守设计，建议 Heydemann 校正后 SDE **≤ 50 nm**。

### 7.4 机械结构中最影响重复定位的误差

按影响排序：

1. **摩擦迟滞（#1）**：双向重复精度中最大的随机误差源。50-300 nm 量级。
2. **反向间隙**：丝杠/联轴器的机械间隙。预压可消除至 < 50 nm。
3. **丝杠周期误差**：每转 ±1-5 μm——但通过全闭环（光栅尺直接测负载位置）可完全消除。
4. **导轨微振**：交叉滚柱导轨的滚动体进出产生的微位移。

### 7.5 滚珠丝杠如何接近 0.5 μm 重复定位？

| 措施 | 效果 |
|------|------|
| C1 级丝杠 + 预压双螺母 | 固有精度 ±3 μm/300mm，回差 < 10 μm → 预压消除到 < 0.1 μm |
| 全闭环（光栅尺直接测负载） | 丝杠的螺距误差、热膨胀 → 全部被位置外环补偿 |
| 速度前馈 + 摩擦补偿 | 减小反向时的过零"突跳" |
| 低速运行（< 5 mm/s） | 减小动态力对重复精度的扰动 |
| 控制周期 ≤ 1 ms | 足够高的伺服刚度抑制外部扰动 |

### 7.6 直线电机的优势和风险

| 优势 | 风险 |
|------|------|
| 无接触力传递 → 零背隙 | 无自锁 → 断电即失控（需额外制动） |
| 无丝杠热膨胀 → 热误差大幅降低 | 成本：无铁芯直线电机 + 光栅尺 + 驱动 ≈ ¥2-5 万/轴 |
| 无丝杠摩擦 → 摩擦迟滞仅来自导轨 | 散热：电机线圈热量直接传导到台面 |
| 重复精度可达 50-150 nm（商业产品） | 对控制品质要求高（无机械阻尼） |

### 7.7 是否建议双反馈控制？

**是，强烈建议。**

| 反馈模式 | 重复精度影响 |
|---------|------------|
| 仅电机编码器（半闭环） | ❌ 丝杠回差 + 热膨胀 + 弹性变形全部进入位置误差 → 5-20 μm |
| 仅自研光栅尺（全闭环） | ✅ 直接测负载位置 → 但机械柔度引发振荡风险 |
| **电机编码器 + 自研光栅尺（双反馈）** | ✅ 电机编码器稳定速度内环，光栅尺精确位置外环——最优方案 |

LinuxCNC 实现方式：PID0 (P+D from rotary), PID4 (I-only from linear), sum2 output.

## 八、自研光栅尺接入闭环工程方案

### 8.1 三种输出模式的处理

| 光栅尺输出 | 处理方案 | 细分方法 | 适用场景 |
|-----------|---------|---------|---------|
| 原始光电信号 | I/V 转换 → 差分放大 → 低通滤波 → ADC 同步采样 | 软件/FPGA CORDIC 反正切 | 最灵活、最可控、自研度最高 |
| 模拟 sin/cos (1 Vpp) | ADC 同步采样 → Heydemann 校正 → CORDIC/atan2 | 电子学细分 (100-4000×) | 最常用、技术成熟 |
| A/B/Z 增量信号 | 正交解码计数器 (4× 基频) | 仅硬件 4×（不够精细） | 如果信号已由前端芯片细分后输出 |

### 8.2 FPGA vs MCU vs SoC 选择

| 方案 | 适合做什么 | 不适合做什么 | 推荐度 |
|------|----------|------------|:----:|
| 纯 MCU (STM32H7) | ABZ 正交计数、简单闭环 | 高倍数 sin/cos 细分（算力不够） | 路线 A |
| **FPGA (Artix-7/ECP5)** | sin/cos 高速采样 + CORDIC 细分 + 时间戳 | 复杂控制算法、Linux 网络通信 | **路线 B（细分部分）** |
| **x86 RT PC** | 复杂控制算法、EtherCAT 主站、数据记录 | 低延迟编码器接口（需要 FPGA 或 Mesa 卡辅助） | **路线 B（控制部分）** |
| Zynq SoC | 以上全部整合、最低延迟 | 开发复杂度极高 | 路线 C |

### 8.3 推荐数据链路（路线 B）

```
光栅尺刻线
    │
    ▼
自研读数头 (LED光源 + 光电二极管阵列)
    │ 原始光电信号
    ▼
信号调理板 (I/V转换 + 差分放大 + 抗混叠滤波)
    │ 模拟 sin/cos (1 Vpp, 差分)
    ▼
ADC (12-14 bit, 同步双通道, ≥ 1 MSPS)
    │ 数字 sin[n], cos[n]
    ▼
FPGA 信号处理流水线:
    ├─ Heydemann 椭圆校正 (偏移/幅度/相位补偿)
    ├─ CORDIC atan2 (16-20 级流水线)
    ├─ 位置累加器 (32-bit, 处理信号周期跨越)
    ├─ 时间戳锁存 (基于 FPGA 硬件定时器, < 10 ns 分辨率)
    └─ 输出接口
          │
          ├─→ (选项 A) SPI / 自定义并行接口 → RT PC
          │
          └─→ (选项 B) EtherCAT 从站 (LAN9252) → IgH 主站
                              │
                              ▼
                    RT Linux (PREEMPT_RT)
                       │
                       ├─ 控制周期同步 (等待新位置数据)
                       ├─ 位置外环 PID + 前馈
                       ├─ 速度指令
                       │
                       ▼ (EtherCAT)
                    伺服驱动 (速度模式 / 电流模式)
                       │
                       ▼
                    电机 → 位移台
```

### 8.4 各级关键参数与风险

| 环节 | 关键参数 | 风险 |
|------|---------|------|
| 读头 → sin/cos | 信号幅度 1 Vpp ±20% | 安装公差敏感，LED 老化 |
| ADC 采样 | 12-14 bit, ≥ 1 MSPS, 同步误差 < 10 ns | ADC 噪声、通道间串扰 |
| Heydemann 校正 | 需要 ≥ 1 个信号周期的运动数据 | 静止时无法校正——首次上电需要小范围"扫频" |
| CORDIC 细分 | 16-20 级流水线，~50-100 ns 处理延迟 | FPGA 资源占用可控 |
| 时间戳 | < 10 ns 分辨率 | FPGA 硬件定时器抖动极小 |
| EtherCAT 反馈 | DC 同步 < 100 ns | 从站芯片配置复杂 |

## 九、闭环控制算法阶段建议

| 算法 | 第一阶段 | 第二阶段 | 不建议 | 理由 |
|------|:----:|:----:|:----:|------|
| **PID** | ✅ 主线 | — | — | 基础。硕士必须掌握且可充分论证 |
| **PID + 速度前馈** | ✅ 主线 | — | — | 消除匀速跟踪误差，必备 |
| **PID + 速度前馈 + 加速度前馈** | — | ✅ 可选 | — | 进一步降低加减速段误差 |
| 位置环/速度环/电流环级联 | ✅ 使用 | — | — | 商业驱动已实现内环，位置外环由 LinuxCNC 实现 |
| 半闭环（仅电机编码器） | ✅ 对比实验 | — | — | 作为对照组，证明全闭环的必要性 |
| 全闭环（仅光栅尺） | ✅ 对比实验 | — | — | 测试稳定性/振荡边界 |
| **双反馈控制** | ✅ 主线 | — | — | 最优方案，论文可详细分析 |
| 摩擦补偿（Coulomb+黏性） | — | ✅ 推荐 | — | 显著改善反向过零精度 |
| 反向间隙补偿 | ✅ 如用丝杠 | — | — | 简单前馈修正 |
| 重复定位误差补偿（激光干涉仪标定） | — | ✅ 推荐 | — | 全行程标定表，进一步提升精度 |
| 振动抑制（陷波滤波器） | — | ✅ 可选 | — | 仅当结构共振明显时需要 |
| 自适应控制 / MPC | — | — | ❌ | 理论要求高，硕士阶段做不深 |

**第一阶段算法组合（4 个核心）**：
1. 双反馈控制架构
2. 位置外环 PID
3. 速度前馈
4. 反向间隙补偿（如用丝杠）

**第二阶段可加**（3 个加分项）：
1. 加速度前馈
2. 摩擦前馈补偿
3. 激光干涉仪标定表补偿

## 十、全过程运动数据监控系统

### 10.1 数据字典

| 类别 | 数据项 | 采集频率 | 用途 |
|------|--------|:----:|------|
| **控制** | 时间戳 (ns 级) | 每控制周期 | 数据对齐 |

## 十二、最终结论

### 1. 这个硕士课题是否成立？

**成立。** 自研光栅尺作为主反馈 + 开放控制架构替代闭源运动控制器 + 全过程数据记录，三个元素组合后有明确的增量贡献。

### 2. 最推荐哪条技术路线？

**路线 B**：RT Linux (PREEMPT_RT) + IgH EtherCAT Master + CiA 402 商业伺服驱动（速度/电流模式）+ FPGA 细分板 + 精密丝杠位移台。位置外环自主实现，商业驱动仅做执行层。

### 3. 第一阶段最小可行平台？

- 自研光栅尺 + STM32/FPGA 读数采集 → LinuxCNC 闭环
- 低成本伺服驱动 + 小行程 C5 丝杠位移台
- 目标：跑通链路，不承诺 0.5 μm
- 硬件预算：< ¥5,000

### 4. 哪些目标可以承诺？

- 小行程 (10-50 mm) 重复定位精度 ≤ 0.5 μm（经交叉验证或激光干涉仪验证）
- 全系统通信协议公开（EtherCAT CoE + CiA 402，全部为国际标准）
- 全过程控制数据可记录、可分析
- 半闭环 / 全闭环 / 双反馈对比实验

### 5. 哪些目标不能一开始承诺？

- 全行程绝对定位精度 ≤ 0.5 μm
- 300 mm 行程的任何精度指标
- 高速运动（> 50 mm/s）下的跟踪精度
- 多轴同步精度

### 6-7. 导师最可能追问及回答话术

**Q1**："你这个课题的创新点到底在哪？"
**A**："不是做传感器，不是买商业方案搭积木。我们的增量在于：(1) 自研光栅尺的信号链全透明接入闭环；(2) 用开放架构实现与商业闭源方案可比的重复精度；(3) 全过程数据可追溯——这让我们的实验结果可审计、可复现。"

**Q2**："你用了商业伺服驱动，不还是闭源的吗？"
**A**："驱动器内部的速度环/电流环确实是我们不打算重做的基础设施——它们的作用类似于数据采集里的 ADC 芯片。核心位置闭环、轨迹规划、误差补偿——这些决定精度的决策都在我们自己的开放控制器上运行。位置外环作为主闭环，内环作为执行层，这种分层在工业界和学术界都是标准范式。"

**Q3**："0.5 μm 重复精度真的能做到吗？"
**A**："在 10-50 mm 小行程条件下，C3 级以上丝杠 + 预压双螺母 + 全闭环控制，商业产品已经做到了 ±0.15-0.4 μm（PI L-511, Aerotech PRO115LM）。我们的差异化在于：用自研光栅尺作为反馈而不是商业光栅尺，用开源控制器而不是闭源运动控制器。目标有可行性参考，不是空想。如果遇到困难，误差预算表已经标识了最大的单项风险——摩擦迟滞——我们有切换直线电机的 Plan B。"

**Q4**："EtherCAT 是 Beckhoff 的私有技术吧？"
**A**："不是。EtherCAT 是 IEC 61158 Type 12 国际标准。有独立开源的主站实现 (IgH, SOEM)，有非 Beckhoff 的从站芯片 (Microchip LAN9252, ASIX AX58100)。我们的系统不依赖任何 Beckhoff 的软件授权，驱动可以选 Delta、Leadshine、Kollmorgen 等任何兼容 CiA 402 的品牌。"
