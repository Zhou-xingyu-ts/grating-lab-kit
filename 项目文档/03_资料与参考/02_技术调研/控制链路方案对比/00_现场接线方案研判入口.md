# 现场接线方案研判入口

> 更新时间：2026-06-03  
> 结论口径：当前现场控制链路仍需进一步调研。EtherCAT 是当前可见接口证据较强的候选路线；CANopen 是赖建君原系统的高置信路线。两者都不能直接写成当前台架已放行接线方案。两条路线共用同一套 DS-BVM、电机、编码器、刹车、STO、电源和运动前安全底座，区别只在主控制器和总线协议层。

## 路线研判表

| 研判项 | EtherCAT：GM1 -> DS-BVM | CANopen：STM32 -> DS-BVM |
|---|---|---|
| 控制器证据 | 现场可见 Panasonic GM1 CSEC16T；官方资料显示 GM1 CSEC16T 属于 EtherCAT 运动控制器 | 赖建君论文和原始代码中存在 STM32H7/CANopenNode 路线；当前台架 STM32H743 板角色未确认 |
| 总线物理接口 | GM1 有 EtherCAT 口；DINGS 板有 ECAT IN/OUT，纸质页列 M10/M11 EtherCAT | DINGS 板有 CAN 口；当前还缺 STM32 到 DINGS CAN 的线缆、收发器和现场报文证据 |
| 工程文件 / ESI / 对象字典 | 已找到 DINGS DS-BVS/BVM EtherCAT XML/ESI 官方下载入口；仍需 GM1 工程导入、扫描和 PDO 实测 | 原始代码中可见 CANopenNode、node ID、PDO/对象字典线索；仍需确认当前台架是否运行该固件 |
| 现有线缆 | EtherCAT 成品网线或转接线方案较直接；自制线序仍需实测 | CAN 线、终端电阻、收发器供电、GND 参考均未闭合 |
| 调试软件 | GM1 工程软件、PANATERM Lite for GM、ServoStudio 可形成分阶段验证链 | STM32 固件、调试器、CAN 分析工具、对象字典访问工具需补齐 |
| 主要风险 | 把“接口匹配”误写成“已扫描/已进 OP/已能发受控命令” | 把“论文原系统”误套成“当前台架实际接线” |
| 下一步验证动作 | 找 GM1 工程、导入 ESI、扫描 DS-BVM、读写最小对象、记录 PDO 和状态机 | 找 STM32 当前接线、固件版本、CAN 收发器、终端电阻、实测 CANopen 报文 |

## 使用规则

- 本目录中的接线、联调和编号文档主要作为路线研究、候选方案和历史参考；当前执行事实以 `../../../02_实验与现场/01_当前执行/` 中的主入口文件为准。
- 先按 [../../../02_实验与现场/01_当前执行/57_共享硬件底座与双总线验证计划.md](../../../02_实验与现场/01_当前执行/57_共享硬件底座与双总线验证计划.md) 区分“共享硬件底座”和“总线差异层”。不要把 STM32/CANopen 另写成一套新的电机、编码器、刹车或 STO 接线。
- 面向现场接线时，先打开 [../../../02_实验与现场/01_当前执行/00_总览.md](../../../02_实验与现场/01_当前执行/00_总览.md)，按安全、验收、未闭环文件采集证据。
- 面向路线判断时，分别进入 EtherCAT 和 CANopen 分组查资料，不把任一路线当成默认接线方案。
- 只有拿到工程文件、现场扫描/报文、端子 pinout、实测记录后，才能把候选路线提升为当前现场接线方案。
