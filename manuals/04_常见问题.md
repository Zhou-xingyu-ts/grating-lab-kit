# 常见问题

| 现象 | 处理 |
|---|---|
| GitHub 看不到仓库/Release | 仓库是私有的，登录 `Zhou-xingyu-ts` 的有权限账号；也可提前下载完整包到 U 盘 |
| 下载后没有 EXE | 下成了 Source code。去 Release 的 Assets 下载完整 `GratingLabKit-Windows-x64-20261031.zip` |
| 缺 Qt/Python DLL，或主窗口闪退 | 完整重新解压；保留 `_internal`；确认 Windows x64，不从 ZIP 内运行。不要从随机网站补 DLL |
| Windows 安全策略拦截 | 保存提示，交由实验室管理员按组织策略核实来源；不关闭防护、不绕过组织策略 |
| `PCANBasic.dll` 找不到 | 由管理员核对 PEAK 驱动和 PCAN-Basic 组件、x64 架构。只复制宿舍电脑 DLL 不能代替系统驱动安装 |
| PCAN 通道打不开/占用 | 核对适配器驱动和通道；Direct 前退出 Servo Studio、PCAN-View 等其他客户端；确认没有另一个采集进程连接 |
| XCAN-USB 无法被驱动识别 | 记录适配器硬件 ID、驱动版本和报错，核对供应商支持版本；未验证前不刷固件或改适配器 |
| SDO 超时 | 不开始运动。核对已批准的电源、CAN 物理链路、终端、Node-ID、bitrate 和主站排他；缺实测不能猜接线 |
| Direct 中找不到修改 Node-ID/bitrate 的地方 | 此入口固定 `PCAN_USBBUS1 / 1 Mbps / Node 1`；不一致就停止使用该直控入口。主窗口只读配置可编辑 |
| 点“停止采集”后电机继续动 | 主窗口只读采集的停止只结束记录。运动由既有控制入口处置；Direct 的停止是“停止并关闭使能” |
| Direct 正常结束后仍有使能 | 这是现有行为；按“关闭使能”并核对状态后退出。未知状态不当作关闭成功 |
| 新电脑没有旧设置/找不到数据 | 设置按 Windows 用户保存，主窗口与 Direct 独立记忆；以界面实际保存目录和会话定位为准 |
| 图中有断线/摘要显示读取失败 | 保留原数据和报错，核对 CAN 负载和采样质量，不插值伪造数据，不自动重试运动 |
| 新会话没有 checksum | 当前版本不再生成新 SHA-256 账本；按会话内容和 manifest/log 检查，老账本保留 |

报告问题时带上：Windows 版本和 x64 信息、上位机标题、驱动版本、报错截图、所用入口、Node-ID/bitrate、会话路径和日志。不要把 GitHub 凭据或系统凭据放进日志。
